# 知玩 · 可交互知识工坊

把想讲清楚或弄懂的知识点，变成可以预测、操作、观察和验证的互动作品。面向知乎黑客松「学习工具与知识生产」赛道。

首版支持梯度下降 `f(x)=x²` 和标准三门问题。知乎搜索提供真实摘要，AI 将选定材料组织成教学草稿；创作者编辑后生成分享链接。实验计算和挑战判分由固定组件执行。

工坊提供「我的作品」：独立保存多份创作与学习草稿，按标题或问题搜索，继续编辑、复制和备份。问题、原始材料和所选来源与作品一同保存；改稿支持撤销与重做，引用来源可直接补充。阅读页可以将作品保存为自己的学习副本。当前以本地产品打磨为主，尚未部署。

## 启动

需要 Node.js 22。首次安装后启动：

```powershell
npm install
npm run dev
```

打开 <http://localhost:3000>。首页和两份示例不需要密钥。

开发脚本在 Windows 自动发现官方 `ZhihuCLI/current/zhihu-cli.exe`。如果 CLI 已通过官方认证并将凭据保存到系统凭证库，搜索和知乎生成即可复用该凭据；设置 `ZHIHU_GENERATION=0` 可关闭知乎生成。程序不会读取或导出凭证库里的明文密钥。其他安装位置可用绝对路径 `ZHIHU_CLI_PATH` 指定。

首次认证请使用官方 CLI 的交互式认证，或其 `auth set --secret-stdin` 安全输入方式。不要将真实密钥放进命令参数、源代码、前端环境变量或项目配置文件。

需要其他端口时，在 PowerShell 直接运行：

```powershell
node scripts/dev.mjs -p 3001
```

## 服务端配置

`.env.example` 只列配置名称。真实值请由部署平台 Secret 管理或服务进程环境注入。生产启动不会自动发现本机 CLI。

| 配置 | 用途 |
| --- | --- |
| `ZHIHU_ACCESS_SECRET` | 官方知乎搜索与可选知乎生成；优先于本机 CLI |
| `ZHIHU_GENERATION=1` | 开启知乎 `zhida-fast-1p5` 生成适配器 |
| `ZHIHU_CLI_PATH` | 官方可执行文件的绝对路径，本地开发可复用系统认证 |
| `AI_BASE_URL` | 可选兼容 Chat Completions 的 API 基址，如 `https://provider.example/v1` |
| `AI_MODEL` / `AI_API_KEY` | 与基址同时配置后优先使用该模型 |
| `TRUST_PROXY=1` | 仅在可信反向代理覆盖客户端转发头时开启 |
| `NEXT_DIST_DIR` | Next 构建目录；开发默认 `.next-dev`，生产默认 `.next` |

`/api/capabilities` 返回配置可用状态，实际认证及服务调用仍可能失败。失败会显示可重试的提示；示例始终可编辑。

## 使用

1. 进入「我想讲清楚」或「我想弄明白」，填写核心问题。
2. 搜索并选择最多三个知乎摘要，或粘贴关键段落。链接用于来源标注，不能自动提取整篇文章。
3. 确认使用标准模型，生成草稿。无关材料会返回不支持。
4. 按开场、探索过程、理解与出处的顺序核对讲解，补充引用，随时撤销或重做改稿。
5. 打开读者视角核对体验，再生成快照链接，或导出 JSON 作品和 Markdown 讲解。
6. 从「我的作品」继续下一次创作；需要换设备时，下载「素材与作品」完整备份并在工坊导入。

素材和未完成的编辑立即保存在当前浏览器，每篇作品有独立地址；刷新可直接继续，暂时清空必填字段也不会丢稿。旧版单草稿保留原数据并迁入作品集。撤销/重做记录用于本次编辑；其他页面会话留下的不同内容可从作品集的恢复记录另存为新作品。存储失败会显示备份入口并保护离开操作；客户端返回后可继续恢复尚未落盘的临时记录，这些记录仅在本次页面打开期间保留。

「导出 JSON 作品」用于阅读与分享；「备份素材与作品」还包含原始材料、问题、检索词和素材来源，两者均可从工坊导入，导入会创建独立作品。作品集没有云端同步或账号系统。

分享 URL 的 `#` 后携带压缩后的作品快照，后续编辑不会改变旧链接。本机链接只能用于本机预览；部署到公开域名后再生成链接，其他人才能直接打开。长链接在部分聊天应用中可能受限，可改用 JSON 文件。

## 验证与构建

```powershell
npm test
npm run typecheck
```

先保持开发服务在 3000 端口运行，再执行浏览器测试（使用本机 Chrome）：

```powershell
npm run test:e2e
```

生产构建使用新目录，以保留已有构建产物：

```powershell
$env:NEXT_DIST_DIR = '.next-release-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
npm run build
npm start
```

构建与启动必须使用相同的 `NEXT_DIST_DIR`。测试报告保存到 `.artifacts/`。项目遵守工作区要求，不执行文件清理或删除。

## 部署条件和边界

支持两个入口：本地 Next.js Node 服务，以及复用同一套 React 组件的线上 Worker。后者通过 `npm run build:public` 构建、`npm run preview:public` 在 3002 端口预览。它不是纯静态站点：知乎接口由 Worker 服务端调用，Site 平台为 `.openai/hosting.json` 声明的 `DB` 提供 D1 数据库。数据库迁移由 `npm run db:generate` 生成，部署包携带迁移文件。

Worker 使用 D1 原子计数：生成每客户端每10分钟最多5次，搜索每分钟最多20次；整个站点每天最多80次知乎上游尝试（UTC+8，每次修复也计入）。80是项目保护值，不是官方额度。客户端标识由可信边缘IP与服务端密钥散列而来，不存原始IP。搜索结果10分钟内复用，同实例合并并发的相同查询。缺少数据库或密钥时接口关闭，示例可继续使用。D1存搜索缓存和计数，不存输入材料或个人探索记录。模型总时限45秒。

Next本地入口仍使用进程内限流与可选官方CLI。仅在可信代理覆盖转发头时开启 `TRUST_PROXY=1`。线上Worker只支持官方知乎HTTP接口及上述共享配额；不加载CLI或可选AI环境配置。

发布后需用真实域名重新检验检索、两类生成、无关材料和分享链接。发布验证见 `docs/release-validation.md`，提报文案、计划书PDF、图标、封面及演示稿位于 `submission/`。运行 `npm run package:public` 会生成保留暂存文件的部署归档，不删除任何文件。仅上传构建产物，源代码单独推送到绑定的私有Site仓库。

知乎摘要可能缺公式和条件，不等于全文。AI 生成的教学文字仍需作者核对。引用链接不代表原作者参与或认可作品。首版不包含知乎站内嵌入、自动发布、账号授权、任意实验代码生成。

演示步骤见 [docs/demo-script.md](docs/demo-script.md)，实际验证记录见 [docs/validation.md](docs/validation.md)。
