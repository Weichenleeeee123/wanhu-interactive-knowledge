# 玩乎 · 把知乎知识变成可以试的体验

> **有些道理，看懂还不够。亲手试一次，才知道自己是不是真的懂了。**

玩乎（Wanhu）是一个和知乎一起工作的可交互知识工具。它不把读者从知乎带走，而是在原文旁边加上一层“可以试一试”的理解体验：

- **在知乎使用**：Chrome / Edge 插件识别文章里的玩乎分享链接，在对应段落下方展开互动卡片；作者也能在知乎写作页选段生成演示。
- **在网页使用**：工坊负责导入知乎内容、组织 AI 草稿、编辑讲解、预览和生成分享快照。
- **对作者**：把一个观点变成读者能预测、操作、观察和核对的互动作品。
- **对读者**：从一段看不懂的文字开始，播放过程、回看分镜、比较行动路径或参数变化，形成自己的理解。

线上地址：[wanhu.asia](https://wanhu.asia) · 插件安装页：[wanhu.asia/extension](https://wanhu.asia/extension)

![玩乎线上首页](public/submission-assets/current/home.png)

## 五秒钟理解玩乎

作者在知乎写作时选中一段：

```
选段 → 玩乎生成互动草稿 → 作者核对与编辑 → 复制 /view#v1... 链接 → 粘回知乎文章
```

读者打开这篇文章后：

```
看到普通链接 → 插件自动识别 → 原文下方展开演示 → 操作 / 追问 / 回到原文
```

没有安装插件的读者也可以直接点击链接进入完整阅读页。分享链接是作品快照，作者后续修改不会悄悄改变已经发布的内容。

## 现在可以做什么

### 知乎插件

2026-09-14 体验修正（随本轮版本发布）：自动跟随选段、识别空白写作页、生成后自动预览、修正草稿地址变化导致的报错；刘看山入口随插件打包。完整核对见 [体验验收与缺口](docs/experience-audit-2026-09-14.md)。

插件是玩乎最贴近知乎的一层：

- 在知乎文章、回答和写作编辑器中读取用户主动选择的文字。
- 连续选段自动更新侧边栏；生成中的作品仍放在最初选择的段落旁。
- 自动识别玩乎 `/view#v1...` 分享链接，并在链接附近插入正文互动卡片。
- 卡片标记为“作者附带的互动演示”，与读者自己生成的理解区分开。
- “在侧边栏继续”会把同一份演示带进插件工作区。
- 本页演示按知乎页面隔离保存在浏览器中，刷新后可恢复。
- 不读取知乎 Cookie，不改写知乎编辑器正文，不自动发布文章。

安装方式见：[插件安装页](https://wanhu.asia/extension)。本地开发版目录是 `dist/extension`，线上版目录是 `dist/extension-public`。

### 网页工坊

工坊有两个产品入口：

- **我想讲清楚**：适合作者、回答者、教师和社群组织者。
- **我想弄明白**：适合从一篇知乎内容或一段材料开始学习的读者。

工坊支持：

- 粘贴知乎文章 / 回答链接，通过官方搜索匹配摘要。
- 浏览黑客松官方知识目录并导入正文材料。
- 选择最多三个来源，保存作者、标题、链接和证据范围。
- 使用 AI 生成教学草稿，再由作者编辑标题、目标、预测、观察、解释、挑战和引用。
- 即时读者预览、撤销 / 重做、作品集、多作品备份和 JSON / Markdown 导出。
- 生成可公开访问的作品快照链接。
- 可展开的轻量辅助：作者检查论证、类比与提纲，读者解释选段与补充概念；直接回答并支持最近 4 轮追问，不会自动生成或覆盖作品。
- 作者默认只核对标题与开场，其余讲解、参数和出处按需展开；读者进入原文与追问视角。

### 让模型按材料选择互动形式

- **SVG 分镜动画**：图形跨帧移动、显隐、变形；可播放、单步、拖动进度、点对象看解释。适合传递过程、空间关系、步骤演化。
- **分支路径探索**：选择条件或行动，查看不同结果，返回换条路；不计分、不设标准答案。适合决策、对比与查证流程。
- **可调参数模型**：安全公式逐步计算，支持回放、选择观察量、固定对照再改变条件。仅在材料有数量关系时使用。
- **梯度下降 / 标准三门问题**：保留现有专用实验与规则解释。
- **原文情境练习**：保留历史作品兼容；生成器仅在明确要求测验时选用，不再作为普通文章默认形式。

AI 返回结构化作品，不能注入 JavaScript、HTML 或任意 SVG 源码。程序校验图形、分支可达性、公式、参数与逐字证据；事实与教学简化仍需作者核对。

## 为什么要和知乎结合

知乎的优势是问题、回答和经验长期沉淀在同一个社区里。它擅长回答“为什么”，但读者遇到复杂因果、反直觉结论或需要前置知识的段落时，仍常常只能继续滚动、搜索，或者离开原文寻找另一个解释。

玩乎补上的是一个很小、但很关键的动作：

> **读者读到一个观点时，不只看到解释，还能马上做一次判断。**

这会让知乎社区里的三种关系更顺畅：

- 创作者把“我想讲清楚”变成一份可操作的讲解。
- 读者把“我好像懂了”变成可以验证的体验。
- 原文仍然是来源、上下文和继续阅读的落点。

## 开发

需要 Node.js 22。

```powershell
npm install
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。

常用命令：

```powershell
npm test
npm run typecheck
npm run build
npm run test:e2e
```

构建本地插件：

```powershell
npm run build:extension
```

构建连接线上服务的插件：

```powershell
npm run build:extension:public
```

然后在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，加载对应目录。代码更新后重新运行构建，再点击扩展卡片的“重新加载”。

## 服务端配置

复制 `.env.example`，真实值只放在服务端环境：

| 配置 | 作用 |
| --- | --- |
| `ZHIHU_ACCESS_SECRET` | 官方知乎搜索、知识库和可选知乎生成 |
| `ZHIHU_GENERATION=1` | 开启知乎直答生成适配器 |
| `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY` | OpenAI 兼容模型服务 |
| `ZHIHU_OAUTH_APP_ID` | 黑客松 OAuth App ID |
| `ZHIHU_OAUTH_APP_KEY` | 黑客松 OAuth App Key，只放服务端 |
| `ZHIHU_OAUTH_REDIRECT_URI` | 已登记的 OAuth 回调地址，线上为 `https://wanhu.asia/api/auth/zhihu/callback` |

OAuth App ID / App Key 已在本地配置，并于 2026-09-14 同步到新 VPS。正式入口已验证跳转知乎授权服务；导航栏提供知乎登录，授权后回到当前作品和角色。当前代码包含 state 防重放、用户资料读取、退出与失效处理；真实用户授权、资料回调仍需登录验收，不将凭证配置等同于完整登录验证。凭证不进入仓库。

## 线上部署

当前生产环境：

- 海外 VPS：`43.110.32.113`
- Node.js + Next.js：监听本机 `3100`
- Caddy：负责 `wanhu.asia` 的 HTTPS 入口
- Cloudflare：DNS 代理、HTTP/3 和边缘缓存
- systemd 服务：`wanhu.service`、`wanhu-caddy.service`

部署原则：

1. 在本地完成测试、生产构建和插件构建。
2. 将已推送的源码打包到新的 releases 目录。
3. 远端安装依赖、运行 `next build`、切换 systemd 工作目录。
4. 通过首页、`/create`、`/view?example=monty-hall`、`/extension`、插件 zip 和 `/api/capabilities` 验收。
5. 不把密钥、OAuth Token 或个人材料放进仓库、分享链接或日志。

## 可信边界

- 普通知乎链接目前通过官方搜索匹配摘要，不承诺读取任意文章全文。
- 黑客松官方知识内容使用无鉴权活动接口，详情路径为 `/story/{work_id}`。
- 分享链接采用 URL Fragment 快照，持有链接的人可以阅读；它不是权限控制。
- 作品与草稿保存在当前浏览器。正文演示折叠可保留本次操作，但读者操作记录没有跨端同步；正文、插件与工坊仍通过快照副本接续，没有共享版本服务。
- “AI 辅助创作”不等于事实已经正确。作品页持续显示来源和核对提示。
- 玩乎不代表知乎官方，不代表原作者参与、授权或认可。
