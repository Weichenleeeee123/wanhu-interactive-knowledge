# 玩乎 · 可交互知识工坊

把想讲清楚或弄懂的知识点，变成可以预测、操作、观察和验证的互动作品。面向知乎黑客松「学习工具与知识生产」赛道，当前已部署到 [wanhu.asia](https://wanhu.asia)。

## 评审材料

- [产品说明计划书](submission/product-description-plan.md)：正式申报文档，包含社区场景、创作思路、技术方案、可信边界和版本计划。
- [提交表单文案](submission/submission-copy.md)：短版项目介绍、创新点和技术摘要。
- [三分钟演示脚本](submission/demo-script-3min.md)：现场演示流程。
- [评审问答与 QA](submission/judge-qa.md)：常见评审问题与产品边界。
- [发布验证记录](docs/release-validation.md)：线上部署、构建和回归验证证据。
- 最新线上截图：[首页](public/submission-assets/current/home.png)、[互动实验](public/submission-assets/current/experiment.png)、[作品集](public/submission-assets/current/library.png)。

支持把知乎文章材料转为「原文互动阅读」：提炼要点、参与情境选择、查看针对性反馈，再对照材料原句。也保留梯度下降 `f(x)=x²` 和标准三门问题的数值实验。创作者可以编辑全部讲解、情境与引用，再生成分享链接。

知乎内容有两个导入入口：官方知识目录可以读取接口提供的正文材料和作者；普通文章、回答链接通过官方搜索精确匹配同一内容的摘要。没有匹配时保留链接，允许补充标题、作者和可阅读的原文段落。不会把相关内容替代目标文章，也不会将摘要称作全文。

工坊提供「我的作品」：独立保存多份创作与学习草稿，按标题或问题搜索，继续编辑、复制和备份。问题、原始材料和所选来源与作品一同保存；改稿支持撤销与重做，引用来源可直接补充。阅读页可以将作品保存为自己的学习副本。当前版本已部署到美国 VPS，通过 Caddy 提供 HTTPS；线上域名、证书和主要页面已完成验收。部署与边界见 [docs/release-validation.md](docs/release-validation.md)。

## 启动

需要 Node.js 22。首次安装后启动：

```powershell
npm install
npm run dev
```

打开 <http://localhost:3000>。首页和两份示例不需要密钥。

开发脚本在 Windows 自动发现官方 `ZhihuCLI/current/zhihu-cli.exe`。如果 CLI 已通过官方认证并将凭据保存到系统凭证库，搜索和知乎生成即可复用该凭据；设置 `ZHIHU_GENERATION=0` 可关闭知乎生成。程序不会读取或导出凭证库里的明文密钥。其他安装位置可用绝对路径 `ZHIHU_CLI_PATH` 指定。

首次认证请使用官方 CLI 的交互式认证，或其 `auth set --secret-stdin` 安全输入方式。不要将真实密钥放进命令参数、源代码、前端环境变量或项目配置文件。

需要其他端口时，在 PowerShell 直接运行：

```powershell
node scripts/dev.mjs -p 3001
```

## 服务端配置

`.env.example` 只列配置名称。真实值请由部署平台 Secret 管理或服务进程环境注入。生产启动不会自动发现本机 CLI。

| 配置 | 用途 |
| --- | --- |
| `ZHIHU_ACCESS_SECRET` | 官方知乎搜索与可选知乎生成；优先于本机 CLI |
| `ZHIHU_GENERATION=1` | 开启知乎 `zhida-fast-1p5` 生成适配器 |
| `ZHIHU_CLI_PATH` | 官方可执行文件的绝对路径，本地开发可复用系统认证 |
| `AI_BASE_URL` | 可选兼容 Chat Completions 的 API 基址，如 `https://provider.example/v1` |
| `AI_MODEL` / `AI_API_KEY` | 与基址同时配置后优先使用该模型 |
| `TRUST_PROXY=1` | 仅在可信反向代理覆盖客户端转发头时开启 |
| `NEXT_DIST_DIR` | Next 构建目录；开发默认 `.next-dev`，生产默认 `.next` |

`/api/capabilities` 返回配置可用状态，实际认证及服务调用仍可能失败。失败会显示可重试的提示；示例始终可编辑。

## 使用

1. 进入「我想讲清楚」或「我想弄明白」，填写核心问题。
2. 在「从一篇知乎内容开始」粘贴链接，或浏览官方知识目录，预览作者和正文并选取段落。也可以搜索摘要或粘贴材料，合计最多三个来源。
3. 写下具体问题，确认生成后核对讲解。一般文章生成 2–4 张情境阅读卡片，标准数学问题使用对应实验；材料不足时提示补充。
4. 按开场、探索过程、理解与出处的顺序核对讲解，补充引用，随时撤销或重做改稿。
5. 打开读者视角核对体验，再生成快照链接，或导出 JSON 作品和 Markdown 讲解。
6. 从「我的作品」继续下一次创作；需要换设备时，下载「素材与作品」完整备份并在工坊导入。

素材和未完成的编辑立即保存在当前浏览器，每篇作品有独立地址；刷新可直接继续，暂时清空必填字段也不会丢稿。旧版单草稿保留原数据并迁入作品集。撤销/重做记录用于本次编辑；其他页面会话留下的不同内容可从作品集的恢复记录另存为新作品。存储失败会显示备份入口并保护离开操作；客户端返回后可继续恢复尚未落盘的临时记录，这些记录仅在本次页面打开期间保留。

导入会追加所选段落，保留已有材料。每个来源与所选正文的对应关系随素材保存，生成时使用完整所选正文校验短引句；能唯一对应来源的引句保留作者与回链。分享快照包含互动卡片、短引句和来源，不包含素材库全文。引句匹配不代表模型解释已经正确，人工修改引用后仍需核对。

「导出 JSON 作品」用于阅读与分享；「备份素材与作品」还包含原始材料、问题、检索词和素材来源，两者均可从工坊导入，导入会创建独立作品。作品集没有云端同步或账号系统。

分享 URL 的 `#` 后携带压缩后的作品快照，后续编辑不会改变旧链接。本机链接只能用于本机预览；部署到公开域名后再生成链接，其他人才能直接打开。长链接在部分聊天应用中可能受限，可改用 JSON 文件。

## 验证与构建

```powershell
npm test
npm run typecheck
```

先保持开发服务在 3000 端口运行，再执行浏览器测试（使用本机 Chrome）：

```powershell
npm run test:e2e
```

生产构建使用新目录，以保留已有构建产物：

```powershell
$env:NEXT_DIST_DIR = '.next-release-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
npm run build
npm start
```

构建与启动必须使用相同的 `NEXT_DIST_DIR`。测试报告保存到 `.artifacts/`。项目遵守工作区要求，不执行文件清理或删除。

## 部署条件和边界

支持两个入口：本地 Next.js Node 服务，以及复用同一套 React 组件的线上 Worker。后者通过 `npm run build:public` 构建、`npm run preview:public` 在 3002 端口预览。它不是纯静态站点：知乎接口由 Worker 服务端调用，Site 平台为 `.openai/hosting.json` 声明的 `DB` 提供 D1 数据库。数据库迁移由 `npm run db:generate` 生成，部署包携带迁移文件。

Worker 使用 D1 原子计数：生成每客户端每10分钟最多5次，搜索每分钟最多20次；整个站点每天最多80次鉴权知乎上游尝试（UTC+8，每次修复也计入）。80是项目保护值，不是官方额度。客户端标识由可信边缘IP与服务端密钥散列而来，不存原始IP。搜索结果10分钟内复用，同实例合并并发的相同查询。缺少数据库或密钥时搜索和生成关闭，示例可继续使用。D1存搜索缓存和计数，不存输入材料或个人探索记录。模型总时限45秒。

`GET /api/materials` 提供官方知识目录；`?knowledge=<目录中的ID>` 读取正文，`?url=<知乎内容链接>` 精确匹配摘要。公开知识接口不需要密钥，不携带鉴权头；固定域名、15秒时限、512 KiB响应上限、10分钟缓存与并发去重。内容入口每实例每客户端每分钟最多30次。Worker 的普通链接匹配复用受配额限制的搜索接口。官方知识正文可能为节选；任意文章全文仍受知乎接口返回范围限制；登录用户 OAuth 读取已提供服务端接口，需配置黑客松 App ID/App Key。

Next本地入口仍使用进程内限流与可选官方CLI。仅在可信代理覆盖转发头时开启 `TRUST_PROXY=1`。线上Worker只支持官方知乎HTTP接口及上述共享配额；不加载CLI或可选AI环境配置。

发布后需用真实域名重新检验检索、两类生成、无关材料和分享链接。发布验证见 `docs/release-validation.md`，提报文案、计划书PDF、图标、封面及演示稿位于 `submission/`。运行 `npm run package:public` 会生成保留暂存文件的部署归档，不删除任何文件。仅上传构建产物，源代码单独推送到绑定的私有Site仓库。

知乎摘要可能缺公式和条件，不等于全文。AI 生成的教学文字仍需作者核对。引用链接不代表原作者参与或认可作品。首版不包含知乎站内嵌入、自动发布、账号授权、任意实验代码生成。

演示步骤见 [docs/demo-script.md](docs/demo-script.md)，实际验证记录见 [docs/validation.md](docs/validation.md)。


## 真实能力配置

玩乎支持服务端接入知乎开放平台和 OpenAI 兼容模型。复制 `.env.example` 为本地环境配置，填写 `ZHIHU_ACCESS_SECRET`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`。黑客松 OAuth 还需在活动后台登记回调地址，并仅在服务端配置 `ZHIHU_OAUTH_APP_ID`、`ZHIHU_OAUTH_APP_KEY`、`ZHIHU_OAUTH_REDIRECT_URI`。OAuth 密钥、授权码和用户令牌不会进入浏览器或日志。

已接入接口：知乎搜索、黑客松知识内容、知识库列表/条目、OAuth 授权登录、授权用户创作/关注/收藏夹读取。上传知识库文件仍需用户明确操作，当前版本只开放读取接口。

刘看山素材位于 `public/mascot/`，用于工坊助手、加载反馈和品牌引导；素材来自知乎官方提供的刘看山动态与三视图资源。
