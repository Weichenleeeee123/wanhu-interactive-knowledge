# 知玩：评委问答准备

口径基于2026年9月12日既有本地验证。每题先给可直接说出的回答，再列追问时需要的证据；公开部署和本轮新体验完成后需校准。

## 1. 为什么必须是知乎？换成任何搜索 API 不是一样吗？

**回答：** 知玩的起点是一个值得解释的疑问。知乎问答可提供问题背景、讲解材料和不同理解方式；我们让用户选择真实摘要参与生成，作品保留来源，实验之后还能回到完整回答继续阅读。目前已经接通这条链路，不只是挂一个知乎 Logo。技术上可以接其他来源，知乎的价值要靠材料相关性和回访行为继续验证，我们还没有证据证明它在所有主题上都优于其他来源。

**追问证据：** 现场展示一次真实搜索、选中摘要进入生成、作品中的来源及原文入口；说明摘要缺公式时需要补充或明确采用标准模型。不宣称已经打通用户收藏、创作历史或站内发布。

## 2. 两个模板是不是太小了，本质只是两个小网页？

**回答：** 首版支持范围确实小，但两个案例共享材料、生成、编辑、协议、阅读和分享，而不是两个完全独立的演示。AI 可以围绕不同问题组织讲解，互动本身由经过验证的组件执行。我们要证明的是这条创作流程能复用。扩展不是把模板名字加进提示词，而是为新主题补齐参数、执行规则、边界和判分，再接入同一协议。

**追问证据：** 在同一编辑器切换两类作品，展示共同字段与不同实验参数。坦诚当前不能把任意文章变成实验，也尚未用第三类组件证明扩展成本。

## 3. ChatGPT 也能解释知识、写互动网页，你们的区别在哪里？

**回答：** 通用聊天工具可以帮助解释甚至生成页面。知玩把一个高频任务整理成完整作品流程：材料来源可回访，草稿可编辑，参数有边界，实验与判分遵循固定规则，结果可快照分享。用户不用自己组织提示词、检查生成代码和搭建页面。我们不主张聊天工具做不到，而是提供一个范围明确、交付方式一致的知识创作工具。

**追问证据：** 演示修改同一知识点的提问和讲解后，实验规则仍保持一致；用独立浏览器打开快照。没有对照实验前，不声称效率高出多少倍。

## 4. 玩过实验就等于学会了吗？你们怎么证明学习效果？

**回答：** 不等于。单轮获胜、反复试到正确答案或点击很多次，都不能证明理解。我们希望让用户先表达预测，再观察实验，最后解释差异并回答新情景题。首版已有实验与固定规则挑战；已增加首次预测锁定和个人探索记录。接下来要看用户能否把规律迁移到新参数或新条件，并通过有对照的评估判断是否优于只读文字。目前没有学习增益数据。

**追问证据：** 梯度下降可更换初值与学习率，检查是否仍能预测下一步；三门问题可追问结论依赖哪些主持人规则。记录行为与正式证明效果是两件事。

## 5. 你们使用知乎内容，版权和原作者权益怎么办？

**回答：** 当前使用接口实际返回的摘要，或用户提交的有权使用的材料，并保留真实来源和原文入口；不自动抓取整篇文章。AI 讲解作为待核对的教学草稿，标准模型单独说明，不能冒充原作者的完整论证。引用链接并不等于获得再创作授权，商业扩展前还需要核对内容使用范围和平台要求，必要时取得授权。

**追问证据：** 展示摘要标识、作者和来源 URL；示例说明采用自行撰写的教学文字。产品不能保证用户粘贴的每段材料都有授权，不把“技术上能生成”解释为“拥有所有权利”。

## 6. AI 幻觉怎么办？如果实验算错，反而会教错人。

**回答：** 我们把可靠性拆开处理。AI 负责组织讲解，作品必须通过结构校验；公式更新、主持人规则和挑战答案由固定组件执行，模型没有修改这些规则的权限。既有版本的测试覆盖数学边界、三门规则、作品结构和主要浏览流程。不过这些测试不能证明每一句 AI 讲解正确，所以生成内容仍是草稿，作者需要核对，读者也能查看来源。

**追问证据：** 梯度下降公式 `x_next=x−η×2x`，包括零初值和震荡边界；三门问题按标准条件枚举规则。无关材料返回不支持，而不是硬套实验。不得把“56项单测通过”说成“内容完全正确”。

## 7. 没有账号和数据库，还能算完整产品吗？线上服务坏了怎么办？

**回答：** 首版围绕单个作品的创作与分享，浏览器保存草稿，链接保存作品快照，已经能支持这条使用路径。代价是没有云端同步、权限管理和实时更新，长链接也受部分渠道限制，所以提供 JSON 备份。检索和生成需要服务端，失败时保留输入并提示重试；预置示例可继续体验，但会明确说明不是现场生成。公网稳定性需要单独验收，不能用本地通过替代。

**追问证据：** 当前基线是56项单测、11项浏览器测试及本地真实集成。完成公开部署后补上真实域名和跨浏览器实测记录；若仍未通过，不声称 Demo 已上线。

## 8. 商业化怎么做？两类免费实验凭什么让人付费？

**回答：** 目前没有付费验证，不会把收入预测当成事实。两类实验先验证创作者是否愿意反复使用，以及分享出去的作品是否有人真正完成。若教学者持续需要更多可靠主题、批量课程作品管理或团队协作，可以测试内容包和工具订阅。决定收费前要核算模型、检索、托管及组件维护成本，并核对内容授权与平台使用条件。

**追问证据：** 先测重复创作、完成率与明确付费意愿，再选择定价和服务对象；尚无营收、付费用户数或市场份额数据。增加模板数量本身不足以构成商业壁垒，可靠内容和创作流程需要持续积累。
