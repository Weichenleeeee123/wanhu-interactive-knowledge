# 玩乎：完整创作流程打磨

用户要求审视项目的功能和体验。本轮固定现有两种实验，不追加实验功能，不部署。

## 已确认的缺口

- 单一草稿键导致多篇作品互相覆盖；原始材料、问题和所选来源只在组件内存中。
- 编辑和重新生成无法撤销；暂时清空必填字段后离开，修改无法保留。
- 没有作品列表；分享页无法保存一份可继续编辑的副本。
- 工坊操作多而缺少清晰的当前作品归属和后续去向。

## 本轮实现

1. `src/lib/works.ts`：每篇作品独立存储，保存问题、材料、来源、模式和可编辑草稿。发布校验与草稿校验分开。保留旧草稿并迁移一次。存储失败明确报告，旧版本覆盖会被拒绝；真正并发交错的内容保存在独立恢复槽中。
2. `src/components/WorkLibrary.tsx` 与 `/library`：按时间展示、按标题/问题搜索、按使用场景筛选、继续编辑、复制作品。空状态指向新建；显示本机存储范围。
3. 工坊采用受控素材状态，输入立即保存；地址绑定作品 ID，刷新直接继续。支持撤销/重做、另存副本、包含原始素材的备份导入导出。新建/导入不覆盖其他作品。
4. 全站导航加入“我的作品”；阅读页支持保存到本机继续编辑。编辑器用阅读顺序组织字段并显示具体错误。
5. 同步本地 Worker 的路由适配，不部署。

## 验证

- 单元测试覆盖独立保存、旧草稿迁移、未完成字段恢复、损坏数据、存储失败和旧版本冲突。
- 浏览器测试走“输入材料→刷新→作品列表→第二篇→返回第一篇→撤销/重做→备份导入”的真实流程；保留现有生成/分享回归测试。
- 检查 360px 和桌面布局、键盘焦点、空状态、错误提示；运行类型检查和生产构建。
- 独立代码审查重点看数据丢失、异步覆盖与用户流程。

已完成本轮实现及验证，记录见 `docs/release-validation.md` 的「完整产品流程迭代」。
