# 可交互知识工坊：首版产品设计

- 日期：2026-09-12
- 状态：选题已确认；本设计稿待审阅
- 工作名称：知玩 · 可交互知识工坊

## 1. 我们要交付什么

让知识创作者把一篇讲解材料，变成读者能动手操作、观察结果、验证理解的互动作品。首版贯通「导入材料 → 生成实验草稿 → 编辑与预览 → 分享 → 读者实验与答题」的完整流程。

参赛方向为「学习工具与知识生产」。主展示案例是梯度下降，第二个案例是三门问题。两者使用同一套创作器、作品数据结构与阅读页面，实验计算由各自的可信组件完成。

产品愿景是降低互动知识作品的创作门槛。首版明确支持两类实验；不会把任意文章都承诺为可以自动转化的实验。

## 2. 谁在什么情况下使用

**知识创作者**已经写过或读过一篇解释性文章，但发现文字难以展示变量变化。例如解释学习率为什么会导致收敛或震荡，希望读者自己拖动学习率观察结果。创作者导入材料，选择实验，调整讲解与初始参数，得到可分享的作品。

**学习者**看过三门问题的文字推导，仍然觉得换门与不换门应该各占一半。学习者先作预测，再亲手玩几轮，最后运行批量实验，对照理论概率并回答挑战题。

以上是待通过产品验证的使用场景，并非已经完成的用户调研结论。

### 产品形态与主要用户（本轮补充，待用户确认）

产品是独立 Web 应用，包含面向创作者的工作台和面向学习者的作品页。首版优先服务知识分享者、学生讲解者和教师；学习者通过分享链接消费作品，也可以将同一流程用于自学。

核心创作单位是「一个值得动手理解的知识点」，而非把整篇长文自动转换为课程。知乎回答里的一段学习率解释，可以成为一份实验作品；一篇涉及多个知识点的文章，需要创作者先选定其中一个目标。

从知乎问题与讲解材料出发，由创作者确认需要解释的疑问，再安排「预测 → 操作 → 观察 → 解释 → 挑战」。AI 提供教学草稿，创作者决定最终表达，实验组件执行经过验证的规则。

独立站点可以接收知乎内容链接并展示来源，但没有证据表明本项目可以内嵌到知乎回答页或自动发布互动作品。首版不把这些平台能力当成既有条件。

## 3. 首版范围与方案选择

| 方案 | 优点 | 代价与判断 |
| --- | --- | --- |
| AI 生成任意可执行页面 | 题材自由 | 生成代码的运行安全、交互可靠性和数学正确性难以在首版控制 |
| 两个独立手工演示 | 容易打磨单个案例 | 无法证明创作者能够生成并编辑自己的作品 |
| **AI 生成结构化草稿，实验组件负责互动** | 创作流程可复用，计算可以验证 | 首版题材受支持的实验组件限制；采用此方案 |

首版包括：材料输入、知乎内容检索入口、实验建议、AI 草稿生成、统一编辑器、即时预览、两类实验、固定规则的理解挑战、本地草稿、分享链接、作品导入导出和来源展示。

后续扩展再考虑傅里叶、贝叶斯、博弈论等组件。账号体系、多人协作、作品广场、收费、自动发布知乎、通用代码生成均不属于本版交付。

## 4. 创作者流程

### 4.1 开始创作

首页用一个可直接操作的小实验解释产品，主入口为「从知乎问题开始」，同时提供「粘贴材料」和「打开示例」。示例明确标注为预置作品。

主流程是输入想解释的问题，检索知乎内容，选择一个主要来源及最多两个补充来源，确认要解释的知识点，再生成实验草稿。展示标题、作者、摘要和原文链接；保留 API 返回链接中的溯源参数。

材料页支持三种起点：

1. 粘贴自己拥有使用权限的讲解文本，填写标题、原文链接和作者信息。
2. 检索知乎内容，选择接口实际返回的摘要作为材料；显示「摘要」，允许补充正文。
3. 载入梯度下降或三门问题的预置教学材料；说明文字自行撰写，附参考来源。

原文链接用于来源标注，不承诺仅凭链接就能读取整篇文章。文本长度限制为 20,000 字符；超限时提示用户选择关键段落，不能静默截断。

### 4.2 生成实验草稿

用户填写希望读者理解的核心问题，例如「学习率为什么不能越大越好」。AI 返回是否适合已支持的实验类型、建议理由、分段讲解、初始参数及挑战题的引导文案。

输入包括创作者选择的实际摘要及补充材料。摘要缺少公式、条件或完整论证时，先提示缺失信息，允许补充；也可由创作者明确采用组件的标准教学模型，例如用 `f(x) = x²` 演示学习率。作品应标注这是用于说明概念的模型，不冒充对原文全部结论的复现。

仅接受 `gradient-descent` 或 `monty-hall` 两种类型。无关材料返回清晰的不支持结果，并展示现有类型的适用范围，不强行生成不相关实验。

生成成功后进入编辑器，所有生成内容标注为待创作者检查的草稿。生成失败时保留输入，允许重试。未配置模型时说明生成暂不可用，同时允许直接编辑预置示例；不会将预置内容伪装成 AI 生成结果。

### 4.3 编辑与预览

桌面采用左侧编辑、右侧作品预览。共享字段包括标题、导语、学习目标、观察提示、结果讲解、挑战引导及来源；实验参数根据所选类型展示。

讲解使用受限的纯文本段落。链接只允许 HTTP 或 HTTPS。用户输入和模型结果都不能作为 HTML 或代码直接执行。

编辑自动保存到当前浏览器的本地草稿，保存状态可见。存储空间不足时保留当前页面中的内容并提示导出。手机端改为「编辑／预览」切换，避免压缩双栏。

### 4.4 分享作品

点击「生成分享链接」前校验必填内容与参数。链接包含当前作品的快照；后续修改生成新的链接。阅读者不需要账号。

作品压缩后放在 URL 的 fragment 中，包含讲解、实验配置、来源信息与结构版本，不包含完整输入材料、运行历史或任何密钥。链接本身承载作品，任何拿到链接的人都可阅读。

编码后的内容上限为 12,000 个字符，超限时提示缩短讲解，并提供 JSON 文件导出。JSON 也可重新导入创作器。该限制是产品约束，仍需验证目标浏览器及消息应用对链接的支持，不能承诺所有分享渠道都兼容。

复制失败时展示可手动复制的完整链接。本地运行时标注链接只指向本机；部署到公开站点后，链接才能供其他设备访问。

## 5. 阅读者体验

作品按「理解问题 → 作出预测 → 操作实验 → 解释观察 → 完成挑战」组织。页面顶部给出学习目标，实验区优先可见。依赖来源的讲解段落关联来源 ID，允许点击查看对应摘要与原回答；文末汇总来源，提供「回知乎读完整解释」。标准模型与本项目补充的教学说明单独标识，不伪装成作者原话。

学习者可以重置实验。刷新后不依赖账号或服务器恢复操作历史；作品配置本身来自分享链接。实验错误、无效链接、版本不支持均有明确页面，且不会覆盖本地草稿。

### 5.1 梯度下降：调学习率，观察小球如何下山

固定目标函数为 `f(x) = x²`，更新规则为 `x_next = x - η × 2x`。首版不接受自定义表达式。

- 创作者设置初始位置、默认学习率、观察提示和解释文案。
- 学习者调整初始位置与学习率，单步前进，或播放、暂停、重置。
- 曲线显示当前位置和轨迹，同时显示步数、当前 x 与函数值；数值与图形来自同一计算结果。
- 初始位置范围为 -10 到 10；学习率范围为 0.02 到 1.20，步长为 0.01。更改参数后重新开始该实验。
- 最多运行 100 步；当 `|x| >= 1,000,000` 或数值不再有限时停止，展示停止原因；不把溢出值继续绘图。
- 对非零初值，`0 < η < 1` 收敛，`η = 1` 等幅震荡，`η > 1` 发散；`η = 0.5` 一步到达 0。初值为 0 时始终停在 0，讲解应体现此例外。
- 挑战题要求预测给定初值和学习率的下一步位置，正确答案由计算模块得到。模型只能编写引导和解释，不能指定判分答案。

参考材料：[如何最简单、通俗地理解梯度下降算法？](https://www.zhihu.com/tardis/bd/ans/2508126669)。此前可查到索引内容，未取得稳定可用的原文抓取接口。示例采用自行编写的说明，不复制全文，也不暗示原作者参与或认可项目。

### 5.2 三门问题：亲手选择，再用实验检验直觉

采用标准三门规则：奖品等概率放在一扇门后，主持人知道奖品位置，始终打开一扇未被选择且没有奖品的门，并始终提供换门机会；有两扇符合条件时随机选择一扇。

- 学习者选择一扇门；主持人开门；学习者选择换门或坚持；系统公布结果。
- 页面明确区分理论概率与本次实验频率。理论上换门胜率为 2/3，坚持为 1/3，有限次数的实验不会保证恰好等于理论值。
- 批量实验支持 100 次和 1,000 次。对同一批奖品位置和初选位置比较两种策略，统计来自实际模拟过程。
- 单轮游戏和批量实验分开计数，避免混淆。
- 创作者可以编辑讲解、观察提示和默认批量次数；主持人规则和理论概率不开放随意修改。
- 挑战题检查标准规则下换门与坚持的概率，并解释其适用前提。正确答案由固定规则得到。

参考材料：[三门问题，为什么概率会上升？](https://www.zhihu.com/tardis/bd/ans/3088391463)。此前可查到索引内容，作者身份尚未核实；界面不编造作者。讲解以可枚举的标准规则为依据，不把参考材料里的所有推理当作已经验证的事实。

## 6. 页面与视觉方向

| 页面 | 主要任务 | 关键状态 |
| --- | --- | --- |
| 首页 `/` | 理解价值，进入创作或示例 | 示例可直接体验 |
| 创作器 `/create` | 导入、生成、编辑、预览和分享 | 输入、生成中、不支持、失败、编辑、已保存、存储失败 |
| 作品页 `/view` | 读取链接或导入作品，完成实验 | 加载、有效、无效、版本不支持 |

视觉采用温暖纸色、深墨色文字与少量蓝橙强调色，围绕实验画布和讲解内容建立层次。用中文系统字体保证首次加载；不用装饰性仪表盘堆砌功能。

拖动控件同时提供键盘可操作的输入方式；图表变化配有数值说明；支持减少动画偏好。阅读页优先保证手机上的门选择、按钮和参数操作可用。

## 7. 技术结构与数据边界

采用 Next.js App Router、React、TypeScript 和 Zod。当前本机 Node.js 22.16.0 满足已查询版本的运行要求。实验图形使用 SVG，核心数学和模拟使用独立纯函数。

核心模块的职责：

| 模块 | 输入与输出 | 依赖 |
| --- | --- | --- |
| 作品协议 | 校验带版本的作品结构及各类型参数 | Zod |
| 内容生成服务 | 材料、学习目标 → 结构化草稿或不支持结果 | 服务端模型适配器、作品协议 |
| 知乎检索服务 | 关键词 → 实际返回的标题、链接和摘要 | 官方 API 或官方 CLI 的服务端适配 |
| 创作器 | 草稿 → 编辑后的有效作品 | 作品协议、预览组件、本地存储 |
| 实验引擎 | 合法参数与动作 → 可验证的实验状态 | 纯计算函数、可注入的随机数来源 |
| 阅读器 | 有效作品 → 讲解、实验与挑战 | 同一套作品组件与实验引擎 |
| 分享编解码器 | 有效作品 ↔ 压缩链接或 JSON 文件 | 作品协议、浏览器压缩能力 |

作品的共享外层包含版本、标题、学习目标、讲解段落、来源数组和实验类型。实验配置使用按类型区分的数据结构。预置作品、AI 生成作品、编辑后作品都必须经过同一校验。标题最多 80 字符，学习目标最多 200 字符，最多 6 个讲解段落且每段最多 800 字符，最多 5 个来源；每条来源的标题最多 200 字符、作者最多 80 字符、URL 最多 2,048 字符。

完整材料只用于本地编辑与用户触发的生成请求；分享时只选择明确的作品字段。来源由用户输入或实际检索结果带入，模型不能凭空添加引用。缺失作者信息时展示「作者信息未提供」。

生成服务采用兼容的模型 API 适配器；密钥仅从服务端进程环境读取，不进入源码、浏览器、分享内容、日志或实际值的 `.env` 文件。可以提供仅含占位符的配置示例。生成设置 45 秒超时；返回格式错误时最多进行一次结构修正尝试，失败后交由用户重试。

读取分享内容时同时限制编码长度、解压后的长度（最多 64 KiB）及字段大小，检查结构版本，拒绝未知字段与非法 URL。没有浏览器压缩能力时保留文件导入导出入口，不伪造分享成功。

## 8. 外部能力的现状与交付边界

- 开始设计时工作区为空，目前仅建立设计文档和工作区约束；官方知乎 skill 和 CLI 已安装。
- 本轮用户提供了知乎凭据，已通过官方 CLI 使用标准输入完成验证并保存到系统安全凭证库，两组各两条结果的实际搜索成功。凭据不写入项目文件。本地 CLI 搜索可用不等于产品后端已接通；部署时仍需配置服务端密钥。
- 当前没有可用的模型 API Key。可以先实现示例、编辑器、实验、分享和服务端适配器；真实模型生成需要有效的服务端配置才能验收。
- 知乎检索入口必须显示真实能力状态。接口不可用时保留粘贴材料与示例入口，不展示虚构搜索结果。
- 本轮已核实搜索字段包含标题、作者、摘要及带溯源参数的原文链接；精选评论字段为可选，不能保证每条都有，也不代表完整评论区。真实结果中存在公式信息缺失，不能将摘要等同于全文或可靠的数学验证。
- 首版采用内容层面的融合：知乎检索参与选题、选定摘要参与草稿生成、作品保留逐段来源并提供原文回访入口。账号层面的「我的创作／收藏」需要另外实现面向每个用户的 OAuth 授权；当前开发者凭据不能代替其他用户授权。
- 已知免费知识接口的内容偏通用学习和职场话题，不能据此承诺能获取本版两个数学案例的全文。
- 模型将收到用户点击生成时提交的材料，按钮附近说明该用途。服务端不持久化材料正文。
- 公开部署前必须验证真实服务调用。首版按单实例 Node 服务部署，生成请求体上限为 128 KiB，同一来源地址每 10 分钟最多触发 5 次生成；多实例部署需要先将限流计数迁移至共享存储。没有凭据的演示必须标明示例模式。
- 目标是交付在线演示与产品说明；本地开发成功、公开部署成功、真实 API 调用成功分别报告，不合并宣称已经完成。

## 9. 验收标准

1. 不配置外部密钥时，两份预置作品可以通过同一创作器编辑、预览、保存、导出和读取分享链接。
2. 配置有效模型后，使用两类适配材料分别真实生成一份作品，修改参数与讲解后仍可正常实验；无关材料得到不支持结果。
3. 配置知乎服务后，关键词检索展示真实返回内容，选取摘要进入创作流程，来源信息保留到作品阅读页。
4. 梯度下降的更新结果、收敛与震荡边界、零初值和停止条件通过纯函数测试；单步、播放、暂停、参数更改和重置的界面行为与结果一致。
5. 三门问题枚举所有初选与奖品位置，验证主持人不会开奖品或初选门，换门恰好在初选错误时获胜；批量结果来自模拟，固定随机源可复现。
6. 分享编解码往返保持作品内容；损坏、超长、非法参数和未知版本输入都得到可理解的错误，不能执行任意 HTML 或脚本。
7. 桌面和手机尺寸分别走完「选择示例 → 修改 → 预览 → 分享 → 阅读 → 操作实验 → 完成挑战」，没有阻断流程的错误。
8. 部署后在另一浏览器环境打开分享链接成功；提交材料说明实际支持的实验类型、原文获取限制、真实 API 使用情况和作品来源。

测试重点放在数学规则、作品边界和主要用户流程。对纯文案、配色等低影响修改不新增镜像测试。

## 10. 实施顺序

先完成作品协议、两类实验引擎与预置作品，再接统一创作器、阅读器、本地草稿和分享。然后接真实模型生成与知乎检索，最后进行浏览器验证、线上部署和参赛说明整理。

创作流程、数学实验、服务端适配器分别保持清晰边界，避免一个文件承载整个项目。首轮跑通流程后再打磨动画与文案。

遵守用户要求：永远不删除任何文件。需要移除已有文件时停止并交由用户处理；开发与安装方式应避免要求覆盖清理已有目录。

## 11. 设计自检

- 两个案例共用创作和阅读流程，且计算规则、可编辑范围与挑战判分边界明确。
- AI 生成与预置示例区分；真实检索与粘贴材料区分；摘要与全文区分。
- 分享不依赖数据库，但长度限制、浏览器要求和部署前提均明确。
- 首版范围支持一个实现计划，未把后续通用实验生成纳入本轮承诺。
- 外部凭据缺失是部分验收项的前置条件，不阻止本地产品流程开发。
