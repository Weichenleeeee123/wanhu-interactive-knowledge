# 玩乎：三分钟演示

## 0:00–0:25 先体验价值

首页调整学习率，让曲线上的位置变化。「同一段知识，有些地方只有亲手试过才容易理解。玩乎让作者把一个知识点做成可分享的实验，也让读者把疑问变成一次探索。」

## 0:25–1:20 从真实知乎材料开始

进入「我想弄明白」，填写「三门问题还剩两扇门，为什么换门的胜率不是一半？」。搜索「三门问题 换门」，打开原文核对，选择有关标准主持人规则的摘要。说明这是检索摘要，可补充缺失条件。确认标准教学模型后生成。

生成需要网络与模型服务。等待期间解释：AI 组织教学文字，已验证的组件负责计算；知乎来源来自真实选择，模型不能虚构引用。

若限流或服务不可用，明确说明当前故障并载入预置示例，不把示例称为现场生成。

## 1:20–2:10 作者核对与读者探索

在编辑器查看生成理由与草稿，修改标题或观察提示。打开三门实验：先选门，再换门，观察结果；运行 1000 次比较换与不换。指出实际频率可能偏离理论值，标准规则下理论概率固定为 2/3 与 1/3。

完成挑战题，点击讲解中的来源，查看真实标题、作者、摘要并返回知乎。来源展开不改变作品链接。

## 2:10–2:40 分享同一份作品

生成分享链接，用另一浏览器打开。读者可以操作实验和答题，不需要编辑器或账号。更改原稿后，旧链接仍保留原来的快照。补充展示 Markdown 讲解导出和 JSON 作品导入。

正式路演使用已经验证的公开域名 https://wanhu.asia。本机链接只用于开发，不能替代评委可访问的作品链接。

## 2:40–3:00 展示扩展方式和诚实边界

打开梯度下降示例：η=0.2 收敛，η=1 等幅震荡，η=1.2 发散（初值不为零）。输入下一步位置并验证。

「两个实验复用同一套材料、编辑、分享流程。当前支持这两类知识点；后续增加经过验证的实验组件，扩展创作者可以讲清楚的内容。」

## 上台前准备

- 在公开域名完成两种真实生成，并导出核对后的作品 JSON 作为备用。
- 保留原文来源和 AI/手动编辑标识，核对讲解中的事实与前提。
- 不连续反复生成消耗额度：单实例默认每 10 分钟 5 次。
- 浏览器演示窗口不展示密钥、后台凭据或无关私人页面。
